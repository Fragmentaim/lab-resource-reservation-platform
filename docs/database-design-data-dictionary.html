实验室资源预约系统数据库设计文档

一、数据库设计说明

根据需求分析，系统涉及用户、资源类型、资源、预约时段以及预约关系五类核心数据。

其中“预约”不是独立实体，而是用户和预约时段之间的多对多联系。由于该联系本身需要记录提交时间和预约状态，因此在关系模式转换时单独形成预约关系。

本设计重点保证实体完整性和参照完整性，使预约记录能够准确关联到用户、预约时段、资源和资源类型。

二、E-R 图说明

用户与预约关系为 M:N：一个用户可以预约多个时段，一个时段可以被多个用户预约。

资源与预约时段为 1:N：一个资源可以提供多个预约时段，一个预约时段只属于一个资源。

资源类型与资源为 1:N：一个资源类型可以包含多个资源，一个资源只属于一个资源类型。

预约时段的开始时间和结束时间作为两个原子属性分别建模。

三、关系模式

说明：下划线为主键，(FK) 表示外键。

图2 关系模式
用户(用户编号, 用户名, 手机号, 角色)
预约(用户编号(FK), 时段编号(FK), 提交时间, 预约状态)
预约时段(时段编号, 资源编号(FK), 开始时间, 结束时间, 总名额)

资源类型(类型编号, 类型名称)

四、外键约束

  • 预约.user_id -> 用户.user_id
  • 预约.slot_id -> 预约时段.slot_id
  • 预约时段.resource_id -> 资源.resource_id
  • 资源.type_id -> 资源类型.type_id
