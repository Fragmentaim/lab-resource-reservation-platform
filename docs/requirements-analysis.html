实验室资源预约系统需求分析文档

一、项目背景

实验室资源预约系统面向学校实验室、设备或场地的日常管理场景。传统线下预约容易出现信息不透明、重复登记、名额统计不及时等问题，因此需要通过 Web 系统对资源、预约时段和用户预约记录进行统一管理。

本系统以“用户选择资源分类和具体资源，再选择可预约时段并提交预约”为核心流程，支持基本的信息维护、查询展示和预约记录管理。

二、系统目标

  • 实现实验室资源、资源类型、预约时段和预约记录的数据库管理。
  • 支持用户查看资源和时段信息，并完成预约操作。
  • 支持管理员维护资源分类、资源信息和预约时段。
  • 保证数据具有基本的实体完整性和参照完整性，避免预约记录脱离用户、资源或时段单独存在。

三、用户角色分析

普通用户：登录系统后查看资源分类、资源列表和预约时段，提交预约并查看个人预约记录。

管理员：负责维护资源类型、资源信息、预约时段，并查看或管理系统中的预约记录。

四、功能需求

  • 用户管理：系统保存用户基本信息，包括用户编号、用户名、手机号和角色，用于区分普通用户和管理员。
  • 资源类型管理：管理员可维护资源类型，例如实验室、设备、会议室等，前端通过分类下拉框筛选具体资源。
  • 资源管理：管理员可维护具体资源，包括资源名称、资源位置和资源状态；用户可按分类查看资源列表。
  • 预约时段管理：管理员为资源设置可预约时段，包括开始时间、结束时间和总名额。
  • 预约管理：用户选择预约时段后提交预约，系统记录预约用户、预约时段、提交时间和预约状态。
  • 查询展示：系统能够按资源分类、资源名称或时段信息展示可预约资源，并展示用户已有预约记录。
  • 基本增删改查：系统应支持资源类型、资源、预约时段和预约记录的新增、删除、修改、查询操作，以满足实验要求。

五、业务规则

  • 一个资源类型可以包含多个资源，一个资源只能属于一个资源类型。
  • 一个资源可以开放多个预约时段，一个预约时段只能属于一个资源。
  • 一个用户可以预约多个预约时段，一个预约时段也可以被多个用户预约，因此用户和预约时段之间是多对多关系。
  • 预约关系需要记录提交时间和预约状态，因此在 E-R 图中将“预约”建模为用户和预约时段之间的关系，并带有关系属性。
  • 预约时段的开始时间和结束时间是两个独立属性，不能合并为一个非原子属性。
  • 当资源或预约时段已被预约记录引用时，删除操作应受到限制或先处理关联数据，避免产生无效数据。

六、数据需求

  • 用户数据：用户编号、用户名、手机号、角色。
  • 资源类型数据：类型编号、类型名称。
  • 资源数据：资源编号、类型编号、资源名称、资源状态、资源位置。
  • 预约时段数据：时段编号、资源编号、开始时间、结束时间、总名额。
  • 预约数据：用户编号、时段编号、提交时间、预约状态。

七、非功能需求

  • 易用性：页面结构清晰，用户能够通过分类和资源信息快速找到可预约时段。
  • 一致性：数据库通过主键和外键约束保证数据关联正确。
  • 可维护性：资源、分类和时段分开管理，便于后续扩展更多资源类型。
  • 安全性：不同角色拥有不同操作权限，普通用户只能操作自己的预约记录。
