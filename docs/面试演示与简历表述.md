# 实验室资源预约平台：面试演示与简历表述

## 三分钟演示顺序

1. **0:00 - 0:35，业务与可靠性**：以热门时段为例说明“先受理、异步确认、请求号查询最终状态”，再点出 Outbox、延迟消息、幂等和缓存失效各自解决的问题。
2. **0:35 - 1:20，可解释知识助手**：上传或展示一份已处理资料，提问后点击引用，说明回答、文档片段、相关度和会话记录如何串成可追溯链路。
3. **1:20 - 2:00，安全工具**：在智能问答页展示 `READ ONLY` 的预约上下文卡片；解释普通用户只能读自己，管理员读他人时 HTTP 层与服务层双重校验，且不向模型返回手机号。
4. **2:00 - 2:35，本地模型与评测**：展示 D 盘模型脚本、RTX 4060 的 Embedding 1024 维输出和 Reranker 相关性排序；再展示 30 题题集和基线报告。
5. **2:35 - 3:00，取舍**：说明当前在线 RAG 基线已可用，本地 GPU 模型已独立验收；下一步是在同题集、同知识源下接入并对比 Recall@K、MRR 与端到端延迟，不夸大未完成结果。

## 可直接使用的简历表述

- 设计并实现实验室资源预约平台，覆盖资源时段、普通/热门预约、取消、签到、提醒与管理员运营；围绕热门预约构建异步确认、幂等保护、缓存失效与延迟消息链路。
- 构建可解释 RAG 工作台：实现文档处理状态、会话恢复、回答引用、分块片段与检索 trace 持久化；建立 30 条中文业务评测集，首轮 30/30 请求成功、可回答题引用覆盖 27/27，平均服务端延迟 8.33s。
- 在 RTX 4060 Laptop 上完成 Qwen3-Embedding-0.6B 与 Qwen3-Reranker-0.6B 本地 GPU 推理验收：Embedding 输出 1024 维向量，Reranker 能将预约取消相关文本排在无关候选之前。
- 实现受权限控制的 `reservation_context` 只读业务工具：普通用户仅能访问自身预约，管理员请求经注解和服务层双重校验；返回最小必要事实并排除手机号等敏感字段。

## 面试追问准备

- **为什么不是直接让大模型查数据库？** 业务工具将身份、权限、字段最小化和事务边界留在 Java 后端，模型只消费只读结果，写操作需要单独确认与审计。
- **100% 指标是否代表模型很强？** 不是。它来自受控小语料和“至少一个关键词命中”的工程基线；真实改进需要固定题集、同知识源，对比 Recall@K、MRR、引用覆盖率、拒答率和延迟。
- **为什么本地 GPU 模型还没有直接替换在线链路？** 先分开验证模型文件完整性、CUDA 可用性、维度和排序正确性，再接入向量库并进行同题集对比，避免一次改动同时引入模型、索引和生成链路的问题。
